# 🎨 ReadQuest UI Guidelines

**Version 1.0**

---

# Why This Document Exists

This document defines the visual language of ReadQuest.

It does not describe implementation.

It does not describe React components.

It defines how ReadQuest should look, feel, and communicate visually.

Every interface should answer one question:

> **Does this help the learner focus on reading?**

If the answer is no,

the design should be simplified.

---

# Design Philosophy

ReadQuest is not a dashboard.

It is not a management system.

It is not an AI chat application.

It is a reading environment.

The interface should disappear behind the story.

Users should remember

the book,

not the interface.

---

# Core Design Principles

## Reading Before Interface

The text is always the primary element.

Everything else supports it.

Nothing should compete with the book.

---

## Calm Before Excitement

The interface should feel calm.

Quiet.

Warm.

Comfortable.

The learner should feel invited to stay.

Not stimulated.

Not overwhelmed.

---

## Beauty Through Simplicity

Remove unnecessary decoration.

Remove unnecessary borders.

Remove unnecessary shadows.

Remove unnecessary labels.

Whitespace is part of the design.

Silence is part of the interface.

# Typography

Typography is the most important visual element.

Beautiful typography is more valuable than beautiful graphics.

Reading text should always be

Large enough

Comfortable

Highly readable

Consistent

Paragraph spacing should improve rhythm.

Line spacing should encourage long reading sessions.

Avoid compressed layouts.

Never sacrifice readability to fit more content.

---

# Reading Width

Reading should never span the entire screen.

Ideal reading width

Approximately 60–80 characters per line.

Large monitors should increase margins,

not line length.

The reading area should feel like a book,

not a document editor.

---

# Layout

Every reading page should contain

One primary reading column.

Optional contextual side panels.

Generous margins.

Comfortable spacing.

Nothing should visually compete with the story.

---

# Visual Hierarchy

Hierarchy should always follow

Book Title

↓

Current Chapter

↓

Reading Content

↓

Reading Companion

↓

Reading Tools

↓

Secondary Information

The learner's eyes should naturally arrive at the story first.

---

# Color Philosophy

Color communicates meaning.

Never decoration.

Color should be used sparingly.

Primary purposes

Reading focus

Current progress

Positive feedback

Reading modes

Avoid rainbow interfaces.

Avoid excessive syntax coloring.

Too many colors increase cognitive load.

---

# Grammar Colors

Grammar colors should support understanding,

not create visual noise.

Only important grammatical relationships should be highlighted.

Colors should be soft,

low saturation,

and visually harmonious.

Grammar coloring should always remain optional.

The learner controls whether it is visible.

---

# Chunk Visualization

Chunks should be visually clear.

The "/" separator should remain subtle.

Chunk spacing should feel natural.

The learner should immediately recognize reading rhythm.

Chunk visualization should never resemble grammar parsing.

---

# Whitespace

Whitespace is functional.

It creates breathing space.

It reduces cognitive load.

It improves reading rhythm.

Never fill empty space simply because it exists.

---

# Cards

Cards should feel light.

Rounded.

Soft.

Floating gently above the page.

Cards should never dominate the interface.

Cards should contain only essential information.

---

# Icons

Icons should be simple.

Rounded.

Friendly.

Consistent.

Every icon should communicate one action.

Avoid decorative icons.

Avoid unnecessary icon labels.

---

# Buttons

Buttons should feel inviting.

Primary buttons should appear only when necessary.

Secondary actions should remain visually quiet.

Buttons should never distract from reading.

---

# Reading Toolbar

The reading toolbar should appear only after text selection.

It should feel lightweight.

Minimal.

Fast.

Never cover the selected sentence.

Toolbar actions

Explain

Translate

Grammar

Generate Image

Listen

Save

Nothing more.

---

# Reading Companion

The dragon should never dominate the interface.

It should occupy a small,

comfortable corner.

Its presence should feel reassuring.

Not demanding.

The dragon should naturally blend into the reading environment.

---

# Progress Indicators

Progress should feel encouraging.

Never stressful.

Preferred

Journey map

Reading path

Chapter completion

Skill growth

Dragon growth

Avoid

Large percentages

Aggressive progress bars

Countdowns

Deadline reminders

---

# Motion

Movement should communicate meaning.

Animations should always have purpose.

Examples

Current sentence gently highlighted.

Dragon slowly breathing.

Current chunk softly glowing.

Book opening naturally.

Avoid unnecessary movement.

Stillness is part of the experience.

---

# Reading Themes

The learner should choose how reading feels.

Suggested themes

Classic Paper

Warm Sepia

Dark Night

Forest

Ocean

Minimal White

Themes should change atmosphere,

not usability.

---

# Accessibility

Every learner should be able to enjoy reading.

Support

Adjustable font size.

Adjustable line spacing.

Adjustable paragraph spacing.

High contrast mode.

Color-blind friendly highlights.

Keyboard navigation.

Screen readers.

Custom reading fonts.

Accessibility should never feel like a separate feature.

It should be built into every design decision.

---

# Responsive Design

Desktop

Centered reading experience.

Tablet

Book-like layout.

Mobile

One-handed reading.

Minimal controls.

The reading experience should remain consistent across devices.

---

# Empty States

Empty pages should encourage exploration.

Never appear unfinished.

Examples

"No books yet."

↓

"Let's begin your first reading journey."

No Reading Plan

↓

"Let's create one together."

No Saved Expressions

↓

"Interesting expressions will appear here."

---

# Loading States

Loading should feel alive.

Examples

The dragon reading a book.

Turning pages.

Writing notes.

Watching stars.

Avoid generic loading spinners whenever possible.

---

# Success States

Success should feel beautiful,

not loud.

Examples

Soft golden glow.

Dragon smiles.

Tiny sparkles.

Book gently closes.

Skill quietly unlocked.

Never use

Confetti.

Screen shaking.

Large popups.

Excessive celebrations.

---

# Error States

Errors should reduce anxiety.

Never blame the learner.

Bad

"Something went wrong."

Good

"We couldn't load this page.

Let's try again."

The learner should always feel supported.

---

# Visual Consistency

Every page should feel like it belongs to the same world.

Spacing.

Typography.

Animation.

Cards.

Buttons.

Icons.

Colors.

Everything should share one visual language.

---

# Emotional Goal

When learners open ReadQuest,

they should feel

"I'm entering a quiet place to read."

When learners close ReadQuest,

they should feel

"I want to come back tomorrow."

Every visual decision should strengthen these emotions.

---

# Final Principle

The interface should never be remembered.

The reading experience should.

If users remember the UI more than the story,

the design has failed.
